Install Proteoscope

Proteoscope is one self-contained program: it needs no Python, packages or other software. One command downloads the release for your computer, checks it and installs it.

$ curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/robert-mcdermott/proteoscope/main/install.sh | sh

Installs the latest release as ~/.local/bin/proteoscope. No sudo, and your PATH is left as it is.

PS> irm https://raw.githubusercontent.com/robert-mcdermott/proteoscope/main/install.ps1 | iex

Run in PowerShell. Installs to %LocalAppData%\Programs\Proteoscope and adds it to your user PATH. No administrator rights needed.

Start it

$ proteoscope

Proteoscope prints a local address, usually http://127.0.0.1:8765, and opens it in your browser. Press Ctrl+C in the terminal to stop it. On Windows, open a new terminal after installing so that it sees the updated PATH. Then continue with Getting started.

Proteoscope runs in your browser. Use Chrome, Edge or Brave, on any desktop system: Proteoscope is developed and tested in these Chromium-based browsers. It needs WebGPU, which Safari provides only from macOS Tahoe (26); Safari on macOS Sequoia or earlier, even Safari 26, does not. Firefox provides it from version 141 on Windows. Browsers without WebGPU get a simplified renderer without surfaces, ambient occlusion or outlines, and say so when Proteoscope starts.

What the installer does

The installer detects your operating system and processor, downloads the matching file and SHA256SUMS from the same GitHub release, and requires exactly one matching checksum. It then runs the downloaded program's --version, and only after both checks pass does it move the program into place, so a failed download never replaces a working copy.

Because it downloads with curl or PowerShell rather than a browser, the program does not get the quarantine flag (macOS) or the mark of the web (Windows), so you are not asked to confirm an unsigned download.

Read it first. Both installers are short scripts in the repository: install.sh and install.ps1.

Versions and install locations

macOS and Linux

Download the installer to read it, then run it with options:

$ curl --proto '=https' --tlsv1.2 -fsSLo install-proteoscope.sh https://raw.githubusercontent.com/robert-mcdermott/proteoscope/main/install.sh
$ less install-proteoscope.sh
$ sh install-proteoscope.sh --version v0.6.0 --install-dir "$HOME/bin"

The piped form reads the same settings from environment variables:

$ curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/robert-mcdermott/proteoscope/main/install.sh | PROTEOSCOPE_VERSION=v0.6.0 sh
OptionEnvironment variablePurpose
--versionPROTEOSCOPE_VERSIONRelease tag to install, such as v0.6.0. Defaults to the latest release.
--install-dirPROTEOSCOPE_INSTALL_DIRAbsolute installation folder. Defaults to $HOME/.local/bin.
PROTEOSCOPE_REPOSITORYGitHub owner/repository, to install from a fork.

For a system-wide installation, download and read the script, then run it with an administrator-owned --install-dir. Never pipe a download straight into sudo sh.

Windows

irm … | iex reads the script into memory and runs it, so the PowerShell execution policy, which governs script files, does not apply. Piping cannot pass parameters: set environment variables instead, or build a script block.

powershell
$env:PROTEOSCOPE_VERSION = 'v0.6.0'
$env:PROTEOSCOPE_INSTALL_DIR = "$HOME\bin"
irm https://raw.githubusercontent.com/robert-mcdermott/proteoscope/main/install.ps1 | iex
powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/robert-mcdermott/proteoscope/main/install.ps1))) `
  -Version v0.6.0 -InstallDir "$HOME\bin"
ParameterEnvironment variablePurpose
-VersionPROTEOSCOPE_VERSIONRelease tag to install. Defaults to the latest release.
-InstallDirPROTEOSCOPE_INSTALL_DIRAbsolute installation folder.
-RepositoryPROTEOSCOPE_REPOSITORYGitHub owner/repository, for forks.
-ArchitecturePROTEOSCOPE_ARCHamd64 or arm64, when detection fails.
-NoPathUpdatePROTEOSCOPE_NO_PATH_UPDATELeave the user PATH unchanged.

To run a saved copy of the installer, bypass the execution policy for that one run instead of changing the setting: powershell -ExecutionPolicy Bypass -File .\install-proteoscope.ps1.

Download and verify by hand

Every release from v0.6.0 on the releases page has the six programs and SHA256SUMS. On macOS or Linux, choose your file from the table above:

$ ASSET=proteoscope-linux-amd64
$ curl -fLO "https://github.com/robert-mcdermott/proteoscope/releases/latest/download/$ASSET"
$ curl -fLO https://github.com/robert-mcdermott/proteoscope/releases/latest/download/SHA256SUMS
$ grep "  $ASSET\$" SHA256SUMS | sha256sum --check -
$ chmod +x "$ASSET"
$ ./"$ASSET" --version

On macOS, use shasum -a 256 --check - instead of sha256sum --check -. In PowerShell:

powershell
$Asset = 'proteoscope-windows-amd64.exe'
$Base = 'https://github.com/robert-mcdermott/proteoscope/releases/latest/download'
Invoke-WebRequest -UseBasicParsing "$Base/$Asset" -OutFile $Asset
Invoke-WebRequest -UseBasicParsing "$Base/SHA256SUMS" -OutFile SHA256SUMS
$Expected = (Select-String -Path SHA256SUMS -Pattern ('  ' + [regex]::Escape($Asset) + '$')).Line.Split(' ')[0]
$Actual = (Get-FileHash -Algorithm SHA256 $Asset).Hash.ToLowerInvariant()
if ($Actual -ne $Expected) { throw 'Checksum verification failed' }
& ".\$Asset" --version

The checksum detects a damaged download and a file that differs from the release's list. Both come from the same release, so it cannot protect against someone able to replace both.

Files downloaded in a browser

The programs are not signed with an Apple or Microsoft certificate, so a file saved from a browser is flagged and the first start asks for confirmation.

  • macOS: a warning such as Apple could not verify “proteoscope-darwin-arm64” is free of malware appears. Open System Settings → Privacy & Security and click Open Anyway next to the message about Proteoscope, or run xattr -d com.apple.quarantine ./proteoscope-darwin-arm64 and then chmod +x ./proteoscope-darwin-arm64.
  • Windows: if SmartScreen blocks the program, click More info, then Run anyway. Or clear the flag first: check Unblock in the file's Properties, or run Unblock-File .\proteoscope-windows-amd64.exe.

Upgrade, go back or uninstall

Run the installer again to upgrade. A failed download, checksum or version check leaves the installed copy as it was, and your sessions and download cache are not touched. Windows cannot replace a running program, so stop Proteoscope first. To go back to an earlier release (v0.6.0 or later), install it by tag with PROTEOSCOPE_VERSION.

To uninstall, delete the program: ~/.local/bin/proteoscope on macOS and Linux, or the %LocalAppData%\Programs\Proteoscope folder on Windows, and remove that folder from your user PATH (Settings → System → About → Advanced system settings → Environment Variables). The download cache can go too:

SystemCache folder
macOS~/Library/Caches/proteoscope
Linux~/.cache/proteoscope (or $XDG_CACHE_HOME/proteoscope)
Windows%LocalAppData%\proteoscope

Build from source

With the Go version named in go.mod or newer:

$ git clone https://github.com/robert-mcdermott/proteoscope.git
$ cd proteoscope
$ go build -o proteoscope .
$ ./proteoscope

Releases can lag behind the main branch; building from source gives you the newest features. The README's Development section covers tests and releases.
