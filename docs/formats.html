Supported files

The files Proteoscope opens, and how it reads structure files, ligand files and density maps.

File types at a glance

Most files can be dragged onto the window; the notes say where else to open them. Files you open are parsed in your browser and never uploaded.

KindFilesNotes
Structures.pdb, .ent, .cif, .mmcif, BinaryCIF .bcif, each optionally compressed with gzip (.gz) or Zstandard (.zst)Click Open local file, drag onto the window, or name on the command line. Several files open together. See below for how each format is read.

Drop the folder or .zip, click Open prediction folder…, or name the folder on the command line. See Predictions and AlphaFold.

Alignments.a3m and .a2m; aligned FASTA (.fasta, .fa, .faa, .afa, .mfa, .msa); Stockholm (.sto, .stockholm); Clustal (.aln, .clustal)Give MSA depth and conservation. For conservation, the first sequence must be the protein. See Analysis.
Docking poses.sdf, .sd and .mol (V2000 and V3000), .mol2, .pdbqtOpen or drop with the receptor active; the molecules become poses in it. See Ligands and docking.

Open the structure first. Docking poses, maps, alignments and PAE files open into the active structure, so open the receptor or model before them. Validation reports and PDFs are not coordinate files; Load report fetches the wwPDB validation report of a PDB entry for you.

Legacy PDB

From PDB-format files (.pdb, .ent), Proteoscope reads:

RecordsWhat is read
Atom records, MODEL/ENDMDLCoordinates and models
HELIX/SHEETSecondary structure
CONECT, SSBONDBonds and disulfides
HEADER, TITLE, COMPND, SOURCE, EXPDTA, KEYWDSHeader metadata
REMARK 2, REMARK 3Resolution and R-free
REMARK 350Biological assemblies
SEQRESThe deposited sequence
DBREF/DBREF1/DBREF2UniProt mappings
Element columnsElements and formal charges

When the element column is missing, the element is inferred from the PDB atom-name alignment, so an alpha carbon is never mistaken for calcium.

PDBx/mmCIF

From PDBx/mmCIF files (.cif, .mmcif), Proteoscope reads:

CategoriesWhat is read
_atom_siteCoordinates, with author and label identifiers, entity IDs, models and formal charges
_entity, _entity_poly, _entity_poly_seqEntities and polymer sequences
_struct_conf, _struct_sheet_rangeSecondary structure
_struct_connBonds: only covalent, disulfide and metal-coordination records become bonds
_pdbx_struct_assembly*, _pdbx_struct_oper_listBiological assemblies
_struct_ref, _struct_ref_seqUniProt numbering
_refine, _reflns, _em_3d_reconstructionResolution and R-factors
Organism and deposition-date categoriesOrganism and deposition date
ModelCIF _ma_qa_metric_localPer-residue pLDDT
_chem_comp_atom, _chem_comp_bondLigand bond orders, aromaticity and charges

BinaryCIF

BinaryCIF (.bcif), as served by RCSB's and PDBe's model servers, is decoded in the browser and read like PDBx/mmCIF.

Predicted models

A structure is treated as a predicted model when it is recognized from:

  • ModelCIF records;
  • the method and software names: AlphaFold, ColabFold, ESMFold, Boltz, Chai-1 or OpenFold;
  • Protenix's data block name.

Every model opened from a prediction folder is one too. For predicted models, the B-factor column is read as pLDDT, rescaled when a predictor writes it on a 0–1 scale. ModelCIF confidences on a 0–1 scale (SWISS-MODEL) are rescaled too.

How structures are interpreted

  • Format. The file name decides between PDB and PDBx/mmCIF, except that a file named .cif without a data block but with PDB atom records is read as PDB.
  • Chain and residue identifiers. Author chain and residue IDs are used for display.
  • Alternate conformers. The highest-occupancy conformer is kept.
  • Bonds come from explicit records plus geometry, using element covalent radii. The geometric step also finds inter-chain disulfides and metal coordination.
  • Bond orders come from the Chemical Component Dictionary, and from duplicated CONECT records in PDB files.

Ligand files

SDF and molfiles (V2000 and V3000), MOL2 and PDBQT are read for docking poses. Open one with the receptor active and its molecules become poses in the receptor. Scores are read from:

  • SD properties: Vina, smina and GNINA affinities and CNN scores, Glide, GOLD and rDock;
  • DOCK's MOL2 comments;
  • Vina's PDBQT remarks;
  • DiffDock's file names, such as rank1_confidence-0.52.sdf.

See Ligands and docking for working with poses.

Density maps

Proteoscope reads CCP4 and MRC 2014 maps (.map, .mrc, .ccp4, optionally gzipped):

  • modes 0, 1, 2, 6 and 12;
  • any axis order;
  • either byte order.

It also reads the PDBe volume server's BinaryCIF. To load the map of a PDB entry rather than a file, see Validation and density maps.

Proteomics files

Proteomics files are read in the browser, and your data is never uploaded. See Proteomics for what Proteoscope does with each.

Search reports

ToolFiles
MaxQuantevidence.txt, peptides.txt, site tables such as Phospho (STY)Sites.txt
DIA-NNreport.tsv, report.parquet (1.9 and 2.x), pr_matrix.tsv, site reports
SpectronautNormal and PTM site reports
FragPipepsm.tsv, peptide and site tables
mzTabPeptide (PEP) and PSM sections, with modification probabilities
Proteome DiscovererPSM and peptide group exports with ptmRS probabilities

Proteoscope keeps the rows of the active structure's proteins, matched by UniProt accession or by sequence, so a multi-gigabyte report of a whole proteome is streamed rather than loaded. Semicolon-separated exports with decimal commas are read as such.

Cross-links

  • The export of xiFDR, xiVIEW, pLink 2/3, MeroX, XlinkX (Proteome Discoverer), MS Annika or MaxLynx.
  • CSV with Protein1, Residue1, Protein2 and Residue2 columns.
  • Pasted links such as A:K123-B:K45.

HDX-MS

  • DynamX state or cluster data.
  • HDExaminer results or uptake summaries.
  • An HDX data table in the community format (Masson et al. 2019).

Pasted data

Some inputs are typed or pasted rather than opened: peptide lists (one per line, with an optional value), sites and variants such as R175H or pS15, and custom per-residue data as chain,residue,value rows.
