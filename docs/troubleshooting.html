Troubleshooting

Fixes for the most common problems, from the renderer badge and failed downloads to installation, and where to ask for help.

The badge says “Canvas preview”

Your browser did not provide WebGPU, so Proteoscope is using a simplified renderer without surfaces, ambient occlusion or outlines. Open the same address in Chrome, Edge or Brave, the browsers Proteoscope is developed and tested in.

  • Safari provides WebGPU only from macOS Tahoe (26). On macOS Sequoia or earlier, even Safari 26 does not, so Safari always shows the simplified renderer there.
  • Firefox provides WebGPU from version 141 on Windows, not yet on Linux or Intel Macs.

To force the compatibility renderer, for example to work around a GPU driver problem, open:

text
http://127.0.0.1:8765/?renderer=canvas

Fetching fails

  • Check your network connection, and make sure Proteoscope was not started with --offline.
  • Read the error message. It shows RCSB's or AlphaFold DB's reply, for example when an entry does not exist.
  • Very large entries can take longer than the 45-second download limit on slow connections. Download the file and open it locally instead.

When the network is down, downloads older than the cache's maximum age are still served from the cache.

The port is already in use

Proteoscope tries the requested port first and then nearby ports. Use the URL printed in the terminal. To ask for a different port, start Proteoscope with --port; see Command-line options.

A downloaded file does not load

  • Use a coordinate file ending in .pdb, .ent, .cif, .mmcif or .bcif, optionally compressed with gzip or Zstandard. Validation reports and PDFs are not coordinate files.
  • Open the structure first. Docking poses, maps and alignments open into the active structure, so open the receptor or model before them.
  • Open the whole prediction. For a prediction, open the whole output folder (or the AlphaFold Server .zip) so the confidence files come along.

Supported files lists every kind of file Proteoscope opens.

Installation problems

These are the most common problems after installing. Install has the full instructions.

The proteoscope command is not found

  • macOS and Linux. The installer puts Proteoscope in $HOME/.local/bin and does not change your PATH. If that folder is not on your PATH, the installer prints the full path to run; run Proteoscope by that path.
  • Windows. The installer adds its folder to your user PATH, but terminals that are already open keep their old PATH. Open a new terminal before running proteoscope.

Windows cannot replace Proteoscope

Windows cannot replace a program that is running, so stop Proteoscope (press Ctrl+C in its terminal) before upgrading, then run the installer again. A failed download, checksum or version check leaves the installed copy as it was. See Upgrade, go back or uninstall.

PowerShell will not run a saved installer

The one-line irm … | iex install is not affected by the PowerShell execution policy. A saved copy of the installer is. Bypass the policy for that one run instead of changing the setting:

powershell
powershell -ExecutionPolicy Bypass -File .\install-proteoscope.ps1

The system warns about a downloaded program

Proteoscope's programs are not signed with an Apple or Microsoft certificate. The installers and the command-line downloads do not go through a browser, so the operating system does not flag the file. A file saved from a browser is flagged, and the first start asks for confirmation. See also Files downloaded in a browser.

macOS. A warning such as Apple could not verify "proteoscope-darwin-arm64" is free of malware appears. Either open System Settings → Privacy & Security, find the message about Proteoscope in the Security section and click Open Anyway, or remove the flag in Terminal:

$ xattr -d com.apple.quarantine ./proteoscope-darwin-arm64
$ chmod +x ./proteoscope-darwin-arm64

If xattr says the attribute was not found, the file was not flagged.

Windows. If SmartScreen blocks the program, click More info, then Run anyway. Or clear the flag before starting it:

  • right-click the .exe, choose Properties, check Unblock on the General tab and click OK; or
  • run this in PowerShell:
    powershell
    Unblock-File .\proteoscope-windows-amd64.exe

Getting help

If your problem is not covered here, open an issue on GitHub. It helps to include the version (proteoscope --version), your operating system and browser, and what the renderer badge says.
